Systems and facts¶

The systems page shows research computing systems on a map and in a list. Each system belongs to an institution and has a scheduler (for example Slurm or PBS). The list shows only systems with a known scheduler.

Where the facts come from¶

  1. LabmillBot reads the public documentation of the system (see LabmillBot). It reads only public pages and never signs in.
  2. A language model reads each page and writes facts: a partition and its limits, a GPU model, a storage path, a software module, how to ask for an account.
  3. Each fact keeps a short quote from the page and a link to the page.

People can also ask Labmill to read a page (see Inspect requests).

How facts are checked¶

Before a fact is published, Labmill checks it:

  • the value has the correct form for its type (for example a number of nodes, a time limit, a host name);
  • the quote is on the page; a fact whose quote is not found gets a lower confidence and the note "quote not verified";
  • host names must belong to the institution;
  • facts that fail a check go to a review list and are not published.

Confidence¶

Every fact has a confidence. It starts from the model's certainty and the checks. Later, job records change it: a job that ran in a partition with a limit confirms the fact, and an error such as "invalid partition" lowers it. Facts that are old or contradicted lose confidence.

A fact is advice, not a promise. When a fact is wrong, open the system page and use Request a change.
